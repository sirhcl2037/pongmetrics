# PongMetrics v0.2

Player setup: name both players, select P1/P2 to set the default for new shots, and use Locate to click a player in the paused video. Locations are timestamped normalized image observations; markers appear only at their recorded frame. They do not track players or permanently bind them to near/far sides. Names can change without changing stable player IDs.

Shots store `playerId` and a separate `playerIdentity: Observation<string>` so identity inference can have its own automatic source/confidence independently of the stroke label. JSON preserves players, locations, and selection. Older v0.2 files import with two default players and their existing shots left unassigned rather than inventing training labels.

Load the original video, set its FPS (25 by default), then pause on a clear table view. Choose **Calibrate table** and click near-left, near-right, far-right, far-left around the perimeter. These labels refer to the camera view. The first point is the origin; x runs across the 1.525 m width and y runs along the 2.74 m length.

The overlay intercepts clicks during calibration or inspection. Turn inspection off to use the video controls. Recalibrate after camera movement, zooms or cuts; one saved calibration describes one fixed camera view. Cancel preserves the previous calibration.

## Why the math works

`geometry.ts` solves eight linear equations for a 3×3 projective transform. Multiplying a normalized image point by this matrix and dividing by its third coordinate gives meters on the table plane. The reverse transform draws the center line and net line back onto the video. The apparent image midpoint is generally not the physical table midpoint under perspective.

Click coordinates are relative to the displayed video image, accounting for letterboxing. Normalizing by image width and height makes calibration independent of browser size. A ResizeObserver keeps the overlay aligned after resizing.

Frame stepping pauses and seeks by 1/FPS seconds on a nominal frame grid. Browser seeking and variable-rate media do not guarantee decoder-level frame accuracy. Timestamps are stored as seconds without display rounding.

## Saving training data

Use **Export JSON** before reloading or changing videos. Load the same video and **Import JSON** to resume. Video bytes are not exported. Version 2 JSON contains video name/size/dimensions/duration, FPS, normalized corner observations, calibration timestamp, and timestamped shot labels with provenance. Import checks matching video metadata and validates values before replacing session state. Metadata is a practical match check, not a cryptographic identity.

`Observation<T>` and `BallObservation` live in `session.ts`. Future manual ball labels and automatic detections can use the same normalized image position format with source and optional confidence. The ball observation list is preserved on import/export; this version does not add a ball-labeling tool or generate ball positions from inspector clicks. Inspector coordinates are table-plane readings, not 3D airborne ball positions.

Run `npm test` on Node 22.18+ or Node 24 for numerical corner mappings, round trips, letterbox normalization, degenerate calibration rejection, and session validation. `npm run build` and `npm run lint` check the application.
